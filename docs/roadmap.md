# خطة المراحل — منصة مكي للمحاماة

**آخر تحديث:** 3 سبتمبر 2026

هذه الخطة مبنية على قرار إعادة استخدام كود new-mistak (أنظر `reuse-plan.md`)، فمعظم Phase 0 و1 نقل وتكييف مش بناء من الصفر.

## Phase 0 — التأسيس التقني

- إضافة Prisma + PostgreSQL لـ `apps/api` (مش موجودين حاليًا).
- إعداد Redis (لطابور BullMQ).
- إنشاء bucket على Backblaze B2 + ربط Cloudflare أمامه (CDN مجاني عن طريق Bandwidth Alliance).
- نقل الـ schema المُكيّف (حذف Booking/Group/GradeLevel، إضافة Payment/Certificate/ConsultationRequest/Instructor/CourseTrack) وعمل أول migration.
- نقل موديولات: `storage`, `transcode`, `worker.ts` كما هي، والتأكد إنها شغالة (رفع فيديو تجريبي وتحويله لـ HLS بنجاح).
- إعداد متغيرات البيئة (`.env`) الجديدة.
- **معيار الإنجاز:** رفع فيديو تجريبي من سكريبت/بوستمان، ويتحول بنجاح لـ HLS ويتخزن على B2.

## Phase 1 — نواة الـ LMS (Backend + Admin + Student Portal)

- نقل وتكييف: `course`, `section`, `lesson`, `exam`, `exam-attempt`, `enrollment`, `attachment`, `student` (auth الطالب).
- إضافة موديول `certificate` (توليد PDF + شرط الإصدار).
- توسيع `auth` الأدمن: دور `INSTRUCTOR` + قيود الصلاحيات (مدرب يشوف/يعدّل كورساته بس).
- **لوحة الأدمن/المدرب:**
  - إنشاء/تعديل كورس أو دورة (عنوان، وصف، غلاف، سعر، نوع، مدرب).
  - إدارة الأقسام والدروس (رفع فيديو مع progress bar، معاينة مجانية).
  - إدارة الامتحانات والأسئلة.
  - متابعة المشتركين وتصحيح الأسئلة المقالية.
- **بوابة الطالب:**
  - تسجيل / دخول.
  - كورساتي ودوراتي + نسبة التقدم.
  - مشغّل الفيديو المحمي (hls.js) + تتبع المشاهدة.
  - أداء الامتحانات + مراجعة النتائج.
  - تحميل الشهادات.
- **معيار الإنجاز:** مدرب يقدر ينشئ كورس كامل (أقسام + دروس + امتحان)، وطالب (مضاف يدويًا للاشتراك مؤقتًا لحد ما الدفع يخلص Phase 2) يقدر يكمّله ويطلع بشهادة. **✅ اتحقق فعليًا** (اختبار حي: مدرب أنشأ كورس + درس فيديو + امتحان، طالب اتفعّل اشتراكه يدويًا، حل الامتحان، والفيديو اشتغل بالكامل).
- **إضافة بعد Phase 1 الأساسية (طلب صريح من العميل):** أسئلة داخل الفيديو
  (Video Checkpoints) — تفاصيلها في `sprints/sprint-video-checkpoints.md`.
  **✅ مُنفَّذة ومُختبَرة حيًّا.**

## Phase 2 — الدفع

- قرار بوابة الدفع: **✅ اتحسم — Kashier** (تفاصيل السبب في `sprints/sprint-payments.md`) بدل ما نستنى قرار نهائي بين Paymob/Kashier، لأن Kashier الوحيدة اللي بتسمح بحساب Sandbox فورًا من غير ما نستنى KYC. Paymob لسه ممكن يتضاف كـ provider تاني بعدين لو احتجنا.
- بناء موديول `payments` خلف طبقة التجريد (`PaymentGateway` interface) — **✅ مبني ومتحقق منه بالـ tests، لسه محتاج حساب Kashier Sandbox حقيقي (`KASHIER_MERCHANT_ID`/`KASHIER_API_KEY`) عشان نختبر الفلو الفعلي كامل.**
- تدفق الشراء: اختيار كورس/دورة → صفحة دفع → webhook تأكيد → تفعيل Enrollment تلقائيًا. **الكود جاهز، لسه محتاج اختبار حي بحساب Sandbox حقيقي.**
- **معيار الإنجاز:** طالب حقيقي يقدر يدفع فعليًا (بمبلغ تجريبي صغير) ويتفعّل اشتراكه أوتوماتيك من غير تدخل يدوي. **⏳ لسه محتاج حساب Kashier Sandbox من العميل عشان نأكده.**

## Phase 3 — الموقع التعريفي والاستشارات

- تصميم نهائي بهوية مكي البصرية (لوجو، ألوان، خطوط) لكل الصفحات الموجودة كهيكل مبدئي: الرئيسية، من نحن، الخدمات، المدونة، اتصل بنا.
- محتوى حقيقي (نصوص، صور الفريق، الخدمات المعروضة فعليًا).
- كتالوج عام للكورسات والدورات (بدون تسجيل دخول، مع دروس معاينة مجانية).
- موديول `consulting`: النموذج + inbox الأدمن + إشعار إيميل عند وصول طلب جديد.
- **معيار الإنجاز:** الموقع جاهز للعرض على الجمهور بمحتوى حقيقي، وطلب استشارة تجريبي بيوصل فعليًا للأدمن.

## Phase 4 — التحسين والإطلاق

- تقارير الأدمن: عدد المشتركين، الإيرادات، نسب إكمال الكورسات (بناء على موديول `reports` المنقول).
- مراجعة أمنية: التأكد من إحكام حماية الفيديو (التوكنات، صلاحية الروابط)، وأمان الـ webhook الخاص بالدفع (التحقق من التوقيع).
- اختبار الحمل الأساسي (خصوصًا مسار رفع/تحويل الفيديو).
- النشر النهائي على VPS (عمليتين PM2: API + Worker)، نسخ احتياطي لقاعدة البيانات.
- **معيار الإنجاز:** المنصة شغالة في الإنتاج، بائع فعليًا كورس/دورة، والفريق قادر يديرها بنفسه من لوحة التحكم.
